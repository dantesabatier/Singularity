# Singularity

**The authoring environment of the Sabatier stack.**

Singularity exists to make the architecture of **Foundation**, **CoreData**, and **Service** tangible.  
It is not a detached editor; it is a living proof that the stack can build full applications with identity, lifecycle, and persistence as first‑class concepts.

---

## What Singularity Proves

Every app generated by Singularity is, by definition, a **Service application** running on **CoreData**, grounded in **Foundation**.  
The point is not merely to generate files, but to **lock the architecture in**:

- **Foundation** provides the object model, collections, KVC/KVO, and system primitives.
- **CoreData** provides the managed object graph, identity, faulting, and persistence.
- **Service** provides the runtime, responder pipeline, and view lifecycle.

Singularity is the authored manifestation of those layers working as a single system.

---

## Why It Matters

Singularity makes application creation feel **effortless**: you can start a real app with a few clicks, edit the model visually, and let the stack do the hard work.  
There is no CLI ceremony and no migration scripts to write; the runtime evolves with the model.

Create a project, model your system, save, and watch CoreData migrate structure and data automatically—no loss, no commands.  
Generate managed object subclasses only when you want a concrete domain layer.  
This is not scaffolding; it is **architectural continuity** from editor to runtime.

Most frameworks treat persistence as plumbing and state as transient.  
Singularity treats the model as the **center of gravity**, so the rest of the system can be honest:

- Objects keep their identity.
- Changes are tracked, not inferred.
- The lifecycle is explicit, not incidental.
- Classes stay clean because the framework carries the infrastructure.
- You never wire routes manually: define a controller or responder and the route exists.

That is what the Sabatier stack was built for. Singularity is where it becomes usable.

## Frontend Workflow (Vite + Latte)

Singularity keeps **server-side rendering with Latte** and uses Vite for modern frontend assets.

- Dev mode (`VITE_DEV_SERVER=http://127.0.0.1:5173`): assets are served by Vite with live updates.
- Prod mode (without `VITE_DEV_SERVER`): assets are loaded from `Build/.vite/manifest.json`.

Commands:

```bash
npm run dev
npm run build
```
